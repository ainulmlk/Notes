FICHE DE RÉVISION — COMMUTATION ET ROUTAGE IP

Comment un paquet trouve son chemin

De vos notes manuscrites à une version consultable : tables ARP et MAC, table de routage, encapsulation et algorithme de transfert d'un routeur, avec un exemple chiffré à chaque étape.

01

Topologie & adressage

Le schéma d'origine montre un réseau local (téléphone, maison, immeuble) relié par deux routeurs à un cœur de réseau qui donne accès à d'autres réseaux.

External network (cloud) Router / switch (S1, R1–R4) End device

@IP vs @MAC

Une adresse IP identifie un appareil de bout en bout, sur l'ensemble du chemin, quel que soit le nombre de routeurs traversés. Une adresse MAC n'identifie une interface que sur le lien local : elle change à chaque saut, quand le paquet passe d'un réseau à un autre.

02

Tables MAC & ARP

Deux tables différentes, deux rôles différents — c'est le piège classique de ce chapitre.

Table d'adresses MAC (sur un commutateur / switch)

Un switch apprend quelle machine se trouve derrière quel port en observant les adresses MAC source des trames reçues. Il s'en sert pour envoyer une trame uniquement vers le bon port, au lieu de la diffuser partout.

Table MAC — exemple
@MACInterface
AA:14:2B:9C:00:01Fa0/1
AA:14:2B:9C:00:07Fa0/3

Table ARP (sur un hôte ou un routeur)

Avant d'envoyer une trame sur le réseau local, un appareil doit connaître l'adresse MAC correspondant à l'adresse IP de destination. La table ARP (Address Resolution Protocol) mémorise cette correspondance IP → MAC pour éviter de la redemander à chaque paquet.

Table ARP — exemple
@IP@MAC
20.0.0.1AA:14:2B:9C:00:01
20.0.0.254AA:14:2B:9C:00:0F
À retenir — table MAC = « qui est branché sur quel port ? » (niveau 2, sur un switch). Table ARP = « quelle adresse MAC correspond à cette IP ? » (niveau 2↔3, sur un hôte ou un routeur).
03

Table de routage

Chaque routeur tient sa propre table de routage pour décider, réseau par réseau, où envoyer un paquet ensuite.

Table de routage de R3 — une ligne
NetworkNext hopInterfaceNb hops
20.0.0.0/24R1e02

Comment lire cette ligne

Network : le réseau de destination visé. Next hop : le prochain routeur à qui confier le paquet. Interface : l'interface locale par laquelle on sort pour l'atteindre. Nb hops : le nombre de routeurs restants à traverser jusqu'à la destination.

Autrement dit : « pour joindre 20.0.0.0/24, j'envoie le paquet vers R1, en sortant par mon interface e0 ; il reste encore 2 routeurs à traverser. »

Correspondance des couches

HTTP → couche Application (les données utiles). TCP → couche Transport. IP → couche Réseau, porte les adresses source et destination de bout en bout. Ethernet → couche Liaison de données, porte les adresses MAC, valables seulement sur le lien local.

Ce qui change / ne change pas à chaque saut — les adresses IP source et destination restent identiques de bout en bout (sauf si un routeur fait du NAT, qui les réécrit volontairement). En revanche, les adresses MAC source et destination sont refaites à chaque saut : la nouvelle adresse MAC source appartient toujours à l'interface du routeur qui vient d'émettre le paquet sur ce lien.
05

Algorithme de transfert d'un routeur

Ce que fait un routeur, dans l'ordre, à chaque paquet qu'il reçoit. Cliquez sur une étape ou utilisez les boutons.

1

Lire et vérifier l'@MAC destination

La trame reçue est-elle bien adressée à l'une de mes interfaces ?

Si l'adresse MAC de destination de la trame ne correspond à aucune de mes interfaces, la trame n'est pas pour moi et elle est ignorée (sauf cas particulier de diffusion/broadcast).
2

Lire l'@IP destination

Le routeur extrait l'adresse IP de destination du paquet, à l'intérieur de la trame.

C'est cette adresse IP — pas l'adresse MAC — qui va servir de clé de recherche dans la table de routage.
3

Consulter la table de routage

Le routeur cherche la ligne de la table de routage dont le réseau correspond à l'adresse IP de destination, pour déterminer où transférer le paquet.

Cette ligne indique le next hop et l'interface de sortie à utiliser — exactement les colonnes vues à l'étape 03.
4

Reconstituer le paquet avec un nouvel en-tête Ethernet

Le routeur ajoute une nouvelle trame Ethernet et l'envoie par l'interface de sortie choisie.

Nouvelle @MAC source = mon interface de sortie. Nouvelle @MAC destination = l'interface du prochain routeur (next hop). Les adresses IP, elles, ne changent pas.
06

Adressage IP & notation /24

Une adresse IPv4 tient sur 32 bits, écrits en quatre groupes de 8 bits (octets) séparés par des points.

20
0
0
1
Network portion — first 24 bits (/24) Host portion — last 8 bits

Lecture du /24

4 octets × 8 bits = 32 bits au total pour une adresse IPv4. Le suffixe /24 indique que les 24 premiers bits (les 3 premiers octets) désignent le réseau ; les 8 bits restants désignent l'hôte à l'intérieur de ce réseau. C'est pour cela que 20.0.0.0/24 regroupe toutes les adresses de 20.0.0.0 à 20.0.0.255.
